# 모임 정산 앱 기획서

## 1. 목적
- **실생활:** 여러 명이 돌아가며 결제한 모임 비용을 "누가 누구에게 얼마"로 자동 정산
- **학습:** AI로 개발하기(Claude Code, CLAUDE.md, Skills, CI)와 AI를 기능으로 넣기(LLM 연동)를 함께 연습
- **포트폴리오:** 알고리즘 + TDD + AI 기능 + 배포까지 갖춘 프로젝트
- **비용:** 0원 (무료 티어만 사용)

## 2. 해결할 문제
여러 명이 각자 다른 금액을 결제하고, 지출마다 해당 인원이 다를 때 정산 계산이 번거롭다.

### 예시 (4명: A, B, C, D)
| 지출 | 결제자 | 해당 인원 |
|---|---|---|
| 숙소 240,000 | A | A, B, C, D |
| 저녁 80,000 | B | A, B, C, D |
| 술 60,000 | C | A, B, C (D 제외) |

**잔액 = 낸 돈 − 쓴 돈**
| 멤버 | 낸 돈 | 쓴 돈 | 잔액 |
|---|---|---|---|
| A | 240,000 | 100,000 | +140,000 |
| B | 80,000 | 100,000 | −20,000 |
| C | 60,000 | 100,000 | −40,000 |
| D | 0 | 80,000 | −80,000 |

- 잔액 합계는 항상 0
- 지출별로 정산하면 송금 8건 → 잔액 상계 후 **3건**: D→A 80,000 / C→A 40,000 / B→A 20,000

## 3. 핵심 로직
1. **분배:** 지출 금액을 해당 인원에게 나눈다
2. **잔액 계산:** 멤버별 (낸 돈 − 쓴 돈)
3. **송금 최소화:** 잔액이 가장 큰 채권자와 가장 큰 채무자를 반복 매칭 (greedy). 송금 건수는 최대 (인원 − 1)
4. **송금 반영:** 완료된 송금을 잔액에 반영해 남은 송금 재계산

## 4. 용어
| 용어 | 영문 | 의미 |
|---|---|---|
| 모임 | Gathering | 정산 단위 (여행, 회식 등) |
| 멤버 | Member | 모임 참여자 |
| 지출 | Expense | 한 번의 결제 (금액, 결제자, 내용) |
| 지출 참여자 | ExpenseParticipant | 해당 지출을 나눠 내는 멤버 |
| 잔액 | Balance | 낸 돈 − 쓴 돈 (+면 받을 돈, −면 낼 돈) |
| 송금 | Transfer | 정산 결과 (보내는 사람, 받는 사람, 금액) |

## 5. 테스트해야 할 경우 (엣지 케이스)
- 나누어떨어지지 않는 금액 (100,000원 ÷ 3명 → 1원 남음)
- 일부 인원만 참여한 지출
- 본인 몫만 결제한 멤버 (잔액 0 → 송금 목록에서 제외)
- 한 사람이 모든 지출을 결제한 경우
- 지출이 0건인 모임
- 일부 송금 완료 후 재계산
- (나중) 비율 분배, 금액 지정 분배

## 6. 결정 사항
| 항목 | 결정 | 상태 |
|---|---|---|
| 분배 방식 (1차) | 균등 분배 + 일부 인원 제외 | 확정 |
| 분배 방식 (확장) | 비율, 금액 지정 | 나중 단계 |
| 1원 단위 나머지 | 결제자 부담. 결제자가 참여자가 아니면 참여자 중 첫 번째 부담 | 확정 |
| 금액 타입 | 원 단위 정수 (long). 소수점 없음 | 확정 |
| 통화 | KRW만 | 확정 |
| 서비스 형태 | 웹 (앱 설치 없음) | 확정 |
| 접근 방식 | 공유 링크. 로그인·초대 없음. 링크를 가진 사람은 누구나 보고 수정 | 확정 |
| 링크 주소 | 추측할 수 없는 랜덤 키 (순번 id를 노출하지 않음) | 확정 |
| 화면 입력 (1차) | 이름 + 낸 금액. 전원 균등 분배 | 확정 |
| 화면 입력 (확장) | [자세히]: 지출별로 참여자 제외 | 다음 단계 |

## 7. 로드맵
| 단계 | 내용 | 배우는 것 |
|---|---|---|
| 1 | 정산 로직 (순수 Java, DB 없이) **(완료)** | TDD, AI와 테스트 먼저 작성 |
| 2 | 모임·멤버·지출 엔티티, Flyway, REST API **(완료)** | JPA, 계층 구조, Testcontainers |
| 3 | 공유 링크 키 + React 웹 화면 (이름·낸 금액 입력, 정산 결과, 링크 복사) | 프론트-백엔드 연동 |
| 4 | GitHub Actions CI, PR AI 리뷰 | 자동화 |
| 5 | [자세히] 입력: 지출별 참여자 제외 (로그인·초대는 하지 않음) | 폼 설계 |
| 6 | AI: 자연어 → 지출 자동 등록 ("숙소 24만 내가 냄") | 구조화 출력, 프롬프트 |
| 7 | AI: 영수증 사진 → 항목별 분배 | 멀티모달 |
| 8 | AI 응답 정확도 테스트셋, 토큰 비용 모니터링 | eval |
| 9 | 송금 완료 체크, 모임 통계 (MyBatis) | 집계 쿼리 |
| 10 | 배포, 모니터링 | 운영 |
| 계속 | 반복 작업은 Skill로 분리 | Skill 설계 |

## 8. 인프라 계획 (무료)
| 구분 | 후보 | 비고 |
|---|---|---|
| 프론트 | Cloudflare Pages / Vercel | 정적 호스팅 |
| 백엔드 | Render 무료 | 512MB, 15분 미사용 시 슬립 → JVM 메모리 튜닝 필요 |
| DB | Aiven 무료 MySQL | 1GB |
| LLM (배포) | Google Gemini 무료 티어 | 사용자별 요청 제한·캐시 필요 |
| LLM (개발) | Ollama (로컬) | 무료, 무제한 |
| 학습용 클라우드 | AWS Free plan (6개월, 크레딧) | EC2/RDS/S3/Bedrock 경험용, 종료 전 무료 플랫폼으로 이전 |
| CI | GitHub Actions | 공개 저장소 무료 |

설계 원칙: Docker 이미지 기반, 환경별 설정은 Spring profile로 분리, LLM은 Spring AI로 감싸 제공자 교체 가능하게.
